# Spec Delta

## Purpose

定义咪窝房间与关联护理区的生活空间、移动端界面和可见家具布置，使玩家能够在同一个家中陪伴猫咪并维护设施，保证多猫活动、家具使用及场景切换具有一致且可恢复的结果。

## ADDED Requirements

### Requirement: 每个咪窝必须提供房间和关联护理区
系统 MUST 将咪窝作为猫咪归属的生活房间，并为每个咪窝关联一个共享护理区。喂食、玩耍、抚摸、梳毛和擦爪 MUST 在房间内进行；猫砂盆、洗澡和吹干 MUST 位于护理区，日常互动近景不得改变咪窝归属。

咪窝 MUST 将食水、休息和活动区域与前往护理区的通路清晰呈现；护理区 MUST 将猫砂维护与洗浴分区，并保留通往设施的可操作路径。基础照护设施 MUST 在首次进入时可用，玩家无需购买家具即可完成基础照护。

#### Scenario: 从房间进入护理区并返回
- **WHEN** 玩家从咪窝进入护理区并返回
- **THEN** 系统恢复原咪窝、仍有效的选中猫与视图状态，不复制猫咪或改变其归属

#### Scenario: 查看两个空间的功能分区
- **WHEN** 玩家进入咪窝或护理区
- **THEN** 咪窝呈现食水、休息、活动和护理区入口，护理区区分猫砂维护与洗浴，并且必要设施和通路清晰可辨

#### Scenario: 不选猫进行公共维护
- **WHEN** 玩家未选猫进入护理区并点击猫砂盆
- **THEN** 系统允许清理或补砂；选择洗澡时才要求选择该咪窝可护理的猫

### Requirement: 房间必须提供初始必要设施
系统 MUST 为初始咪窝提供基础食盆、水碗、休息位置、猫砂盆、猫砂铲、梳理工具与配置数量的初始猫砂。增加猫咪时 MUST 提供有名字的对应食盆，同窝护理设施共享；水碗不引入独立付费口渴循环。

#### Scenario: 首次进入咪窝
- **WHEN** 玩家首次进入初始咪窝
- **THEN** 系统在正确空间展示必要设施和初始物资，并允许玩家完成基础照护而无需先购买装饰

### Requirement: 移动端界面必须保持空间和操作可见
系统 MUST 提供咪窝名称、货币、最多三只猫的选择入口及商店、背包、布置和护理区入口，并适配安全区域及微信胶囊。系统 MUST 明确选中对象，近景保留房间上下文，操作时保留停止或返回入口，不以常驻属性面板遮住猫咪。

玩家查看单只已拥有猫咪的当前状态时，MUST 从咪窝选择该猫并进入猫咪实例详情；详情返回 MUST 恢复原咪窝与该猫的选中状态。猫咪图鉴用于品种收集资料，不作为单只猫咪实例详情的直接入口。

#### Scenario: 在不同竖屏设备选择猫咪
- **WHEN** 玩家在目标长短屏或带安全区域的设备上选择猫并展开动作菜单
- **THEN** 猫咪、菜单、关闭入口和必要操作按钮保持可见可触达，选择第二只猫不误操作第一只猫

#### Scenario: 从咪窝查看单只猫咪详情
- **WHEN** 玩家在咪窝选择一只已拥有的猫并打开“详情”
- **THEN** 系统展示该猫咪实例的资料；返回后恢复原咪窝和该只猫的选中状态

#### Scenario: 打开商店面板
- **WHEN** 玩家打开商店或其他模态面板
- **THEN** 系统阻止点击穿透到场景，关闭后恢复正确输入状态

### Requirement: 已购家具必须经过有效布置才在空间中生效
系统 MUST 让玩家在布置模式中放置、移动、按支持方向旋转和收回拥有物，并在确认时保存完整布局。取消 MUST 恢复进入布置前的布局；购买但未摆放的家具 MUST 留在背包而不视为房间已有物。

布置 MUST 使用可见或明确提示的吸附位置，并根据家具配置校验占地、适用空间和可旋转方向；家具不得与必要通路或设施冲突。

布置清单 MUST 仅包含家具及商品配置明确标记为可摆放的玩具；食物、猫砂和其他日用品 MUST NOT 作为场景家具摆放。玩具是否可摆放由商品配置决定，不由其耐用或消耗类型推断。

#### Scenario: 购买并布置猫爬架
- **WHEN** 玩家购买猫爬架后从背包放到合法位置并保存
- **THEN** 系统在房间显示同一实例的猫爬架，并将其标记为已摆放

#### Scenario: 布置时筛选可摆放物品
- **WHEN** 玩家从布置模式打开拥有物列表
- **THEN** 系统只提供家具和配置为可摆放的玩具，不提供食物、猫砂或其他日用品作为摆放目标

#### Scenario: 取消移动家具
- **WHEN** 玩家移动或收回多个家具后取消布置
- **THEN** 系统恢复本次进入前的完整布局，不丢失、复制物品或扣款

### Requirement: 布置必须维护实例唯一性和必要设施可达性
系统 MUST 拒绝重叠、越界、阻断门或必要设施路径、放错场景及重复摆放同一实例的布局，并说明原因。最后一套必要设施 MUST 在替换成功前保持可用，使用中的家具 MUST 先安全释放占用。

#### Scenario: 猫砂盆放入房间
- **WHEN** 玩家将猫砂盆拖入咪窝房间而不是护理区
- **THEN** 系统拒绝保存并提示适用空间，保留原布局

#### Scenario: 家具阻断入口
- **WHEN** 布置将阻断护理门或食盆的可达路径
- **THEN** 系统指出无效位置和原因，不提交部分非法布局

#### Scenario: 重复实例或撤回必要设施
- **WHEN** 玩家重复放置已在其他咪窝使用的同一实例，或试图收回最后一套必要设施
- **THEN** 系统拒绝操作且不改变已保存布局和物品所有权

### Requirement: 可交互家具必须被猫咪实际使用
系统 MUST 让已布置且可达的猫床、猫爬架、纸箱、抓板及地面玩具分别支持休息、登高、进入、抓挠和玩耍。家具和装饰 MUST 仅提供外观、休息位置或互动锚点，不得提供饱食度、清洁度、心情、信任、精力等属性加成，也不得改变属性衰减速度。使用家具时发生的互动效果仍 MUST 遵循对应互动规则和收益上限；纯装饰 MUST 明确只影响外观。

#### Scenario: 猫自主选择家具
- **WHEN** 猫空闲且存在符合状态、可达且未占用的已布置家具
- **THEN** 猫能够走向并使用该家具，而不穿墙、使用未摆放物或被玩家邀请强制打断必要活动

#### Scenario: 查看家具用途与效果
- **WHEN** 玩家查看家具或装饰的商品详情
- **THEN** 系统说明其外观、休息位置或互动用途，不展示被动照护数值加成；家具数量不提高属性、信任或互动收益

#### Scenario: 在使用中移动猫床
- **WHEN** 玩家进入布置并移动被猫使用的床
- **THEN** 系统等待占用结束或先将猫安全移至可达空闲站位，再允许移动，不留下失效使用状态

### Requirement: 场景切换必须保持单一猫咪和设施活动
系统 MUST 在房间与护理区之间保持同一只猫的逻辑身份、主要活动和设施占用；玩家不在护理区时如厕可继续，但不得强制切换镜头。转移咪窝 MUST 先完成或退出必要护理并释放原占用，不复制共享家具及猫砂。

#### Scenario: 猫在护理区时返回房间
- **WHEN** 一只猫仍在护理区活动而玩家返回房间
- **THEN** 房间标明该猫位置，不在房间生成第二只实体

#### Scenario: 猫在多个咪窝间转移
- **WHEN** 合法转移完成
- **THEN** 系统释放原设施占用并使用新咪窝的布局和盆状态，不把原咪窝猫砂或家具复制过去
