# Spec Delta

## Purpose

定义玩家如何在咪窝房间与护理区照顾猫咪，通过需求、情绪、信任及个体偏好形成双向互动，并完成猫砂维护、洗浴和疾病治疗，支撑闯关之外可理解、可恢复且偏治愈的持续养成循环。

## ADDED Requirements

### Requirement: 猫咪需求状态必须随经过时间变化
系统 MUST 维护每只猫咪的饱食度、清洁度、心情、精力及健康状态，数值属性限制在 0 至 100；离线时间 MUST 计入按配置计算的需求衰减和休息恢复。精力不足 MUST 限制追逐类互动，不新增未照护疾病条件。

#### Scenario: 在线或离线时间推进属性衰减
- **WHEN** 猫咪上次状态更新时间之后经过一个或多个衰减周期
- **THEN** 系统按经过周期数及该猫咪的衰减系数更新饱食度、清洁度和心情，并将数值限制在 0 至 100

#### Scenario: 玩家重新进入游戏
- **WHEN** 玩家在一段离线时间后打开游戏
- **THEN** 系统根据已记录的时间差补算猫咪状态，不把离线时长误认为零

#### Scenario: 精力不足后休息
- **WHEN** 猫咪精力不足且经过配置的休息周期
- **THEN** 系统按配置恢复精力；恢复前不强制猫咪继续追逐，数值不超出 0 至 100

### Requirement: 玩家必须能使用互动改善猫咪状态
系统 MUST 提供喂食、洗澡、吹干和玩耍。喂食成功 MUST 同时扣食物并增加饱食度；玩具 MUST 按商品类型区分耐用和消耗型。成功前拒绝或取消 MUST 不扣物品，拒绝须说明原因；表现动画不得重复结算。

#### Scenario: 喂食猫咪
- **WHEN** 玩家选择可用食物且猫愿意接受、饱食度未满并成功执行喂食
- **THEN** 系统立即扣除一份食物并按配置增加饱食度至不超过 100，后续进食动画或其恢复不重复增加属性或扣物品

#### Scenario: 猫拒绝或玩家取消喂食
- **WHEN** 猫已饱、拒绝接受或玩家在成功前取消
- **THEN** 系统保持库存、饱食度和最后成功喂食时间不变，并解释原因

#### Scenario: 喂食动画中退出
- **WHEN** 喂食已经成功结算而玩家退出或重启
- **THEN** 已结算效果保留，恢复或跳过动画均不再次发放效果；动画中的食物不得再次使用、返还或换口味重复结算

#### Scenario: 在冷却期内再次洗澡
- **WHEN** 猫咪距离上次洗澡尚未达到洗澡冷却时间
- **THEN** 系统拒绝再次洗澡并显示剩余冷却时间

#### Scenario: 洗澡后完成吹干或协助擦干
- **WHEN** 玩家完成吹干，或选择系统协助擦干
- **THEN** 系统清除湿润状态，按已完成护理阶段结算一次清洁效果，不因吹干操作失误或协助完成触发感冒

#### Scenario: 使用玩具互动
- **WHEN** 玩家使用已拥有耐用玩具或有库存的消耗型玩具完成有效互动
- **THEN** 系统按配置增加限额内的心情，耐用玩具不扣实例，消耗型玩具在首次有效使用时仅扣一次

### Requirement: 猫咪必须归属有容量限制的咪窝
系统 MUST 为玩家提供初始咪窝，每个咪窝最多容纳三只猫，并允许玩家在其有空位的咪窝之间转移猫咪。

#### Scenario: 转移猫咪到有空位的咪窝
- **WHEN** 玩家将猫咪转入尚有空位的咪窝
- **THEN** 系统更新猫咪所属咪窝

#### Scenario: 咪窝已满
- **WHEN** 玩家尝试将猫咪转入已有三只猫的咪窝
- **THEN** 系统拒绝转移且不改变猫咪归属

### Requirement: 生病猫咪必须能接受诊断和治疗
系统 MUST 根据配置的疾病条件和猫咪抗性判定疾病，向玩家展示生病状态，并仅在玩家确认且拥有足够喵币时完成治疗。

#### Scenario: 需求状态触发疾病判定
- **WHEN** 猫咪的饱食度低于 20 且清洁度低于 30
- **THEN** 系统按基础 30% 概率及猫咪抗性执行疾病判定

#### Scenario: 玩家治疗且余额足够
- **WHEN** 玩家确认一只生病猫咪的治疗且喵币不少于该疾病费用
- **THEN** 系统扣除治疗费用、清除疾病状态并恢复健康

#### Scenario: 玩家余额不足以治疗
- **WHEN** 玩家确认治疗但喵币少于该疾病费用
- **THEN** 系统不扣款且不改变猫咪疾病状态，并提示余额不足

#### Scenario: 治疗后的短期免疫
- **WHEN** 猫咪完成治疗
- **THEN** 系统在接下来的 24 小时内避免再次触发疾病

### Requirement: 猫咪回应必须来自可理解的状态和偏好
系统 MUST 分开记录即时情绪、长期信任和个体偏好，并根据需求、活动及偏好决定接受、暂停或拒绝。系统 MUST 通过姿态和必要短提示解释回应，不随机判失败；未回应邀请、停手或一次误操作不得降低长期信任。

#### Scenario: 猫不想被摸
- **WHEN** 猫疲劳、紧张或玩家触碰不喜欢的位置
- **THEN** 猫通过转身、甩尾或轻挡表达暂停，系统停止有效收益并提示原因，玩家可结束或等待而不受失败惩罚

#### Scenario: 未回应主动邀请
- **WHEN** 猫叼来玩具或靠近邀请抚摸而玩家未回应
- **THEN** 猫稍后选择其他活动，不强制打开界面、不扣信任且不产生倒计时任务

### Requirement: 玩耍必须响应操作节奏并限制重复收益
系统 MUST 让猫对玩具追踪、伏低、扑击、抓住及休息作出可见回应。慢移和停顿 MUST 提供可抓住机会，拖动过快须给可理解提示；空拖、重复开启及超出配置限额不得无限增加心情或信任。

#### Scenario: 玩家让猫抓住玩具
- **WHEN** 猫愿意玩且玩家在活动范围内慢移后停顿
- **THEN** 猫能完成扑击和抓住表现，心情按有效会话结算而非逐帧增加

#### Scenario: 疲劳时继续拖动
- **WHEN** 猫精力不足而玩家继续移动玩具
- **THEN** 猫休息且不继续计有效追逐收益，玩家可以收起玩具

### Requirement: 抚摸和日常清洁必须允许停手及部分完成
系统 MUST 在房间提供抚摸、梳毛和擦爪，依据部位、节奏及意愿反馈。玩家松手、取消或猫离开时 MUST 停止当前操作；已完成的清洁区段保留效果，同一干净区段不得重复刷收益，精细拖动须有点选等价入口。

#### Scenario: 部分梳理后退出
- **WHEN** 玩家完成部分梳毛或擦爪后退出
- **THEN** 系统保留有效清洁效果，继续同一区段不会重复获益，猫缩爪或走开时不被强制继续

#### Scenario: 抚摸结束
- **WHEN** 玩家停止滑动或猫表达暂停并离开
- **THEN** 抚摸动作停止，无失败结算，玩家仍能观察猫咪或返回房间普通视角

### Requirement: 猫砂盆必须按时间提供有限的日常如厕循环
系统 MUST 根据经过时间和同窝猫数补算如厕需求，猫使用可用盆后增加唯一可清理结团并扣除配置砂量。盆内余量不得为负，结团累积不得超过配置容量；跨自然日不强制整盆更换，超长离线不产生无限积压或新增疾病及收容触发条件。

#### Scenario: 猫自主使用猫砂盆
- **WHEN** 猫有如厕需求且盆可用、未被占用
- **THEN** 猫进入并使用猫砂盆，完成后增加结团、扣砂并释放占用，表现不展示排泄细节

#### Scenario: 长时间离线和重复补算
- **WHEN** 玩家长时间离线后返回，或再次处理同一时间范围
- **THEN** 系统只对未补算时间应用有容量边界的累积，不重复生成结团；补算游标前进以避免恢复后重放超额积压

#### Scenario: 盆不可用
- **WHEN** 猫砂不足或污物达到盆容量
- **THEN** 系统提示清理或补砂，停止超容量累积，不自动购买、不因此新增疾病判定

### Requirement: 铲屎必须只在实际丢弃时清除结团
系统 MUST 提供选中结团并丢入容器的清理操作及点选等价入口；未丢弃或取消须保留结团，已清理结团不得重复删除。猫砂铲可重复使用，铲屎不得另收货币或默认发放可无限刷取的货币。

#### Scenario: 铲子未到容器就松手
- **WHEN** 玩家铲起结团后在废弃容器外松手或取消
- **THEN** 结团回到盆内，盆状态与库存不变

#### Scenario: 丢弃并重复提交
- **WHEN** 玩家完成丢弃并重复提交同一结团清理
- **THEN** 系统只删除一次该结团，后续返回既有结果，不重复改变砂量、费用或收益

### Requirement: 补砂和整盆更换必须原子处理计量
系统 MUST 在补砂前展示库存、盆缺少量和实际填入量，按实际量同时扣库存及增加盆内余量，并保留包装剩余量。整盆更换 MUST 在新砂充足且玩家确认后一次处理旧砂和填新砂；取消、盆满或库存不足不得破坏原盆。

#### Scenario: 仅补少量猫砂
- **WHEN** 盆缺少量小于一包猫砂且库存充足
- **THEN** 系统只扣实际填入量并保留包装剩余量，盆内不超容量

#### Scenario: 整盆更换库存不足
- **WHEN** 玩家尝试整盆更换但新砂不足或取消确认
- **THEN** 系统不倒掉旧砂、不改库存，并提示原因或保持原操作前状态

### Requirement: 猫咪和设施活动必须互斥并可释放
系统 MUST 保证同一只猫只有一种主要活动，同一设施按配置容量占用，猫砂盆单次只供一只猫使用。使用中不得维护猫砂盆；取消、场景离开或恢复时须保留或重建有效占用而不重复执行，异常占用须显式恢复并提示。

#### Scenario: 三只猫依次如厕
- **WHEN** 三只猫同时有需求而只有一个共享猫砂盆
- **THEN** 只有一只成功占用，其他猫等待或选择其他可行活动，不同时结算同一占用

#### Scenario: 如厕中尝试清理或洗澡
- **WHEN** 玩家维护使用中的盆，或选择正在如厕的猫洗澡
- **THEN** 系统拒绝并说明使用中，状态和物品不变

### Requirement: 洗浴必须可暂停并安全完成或恢复
系统 MUST 记录准备、湿润、清洗、冲净、擦干和吹干阶段。工具松手必须停止，紧张时可暂停安抚。弄湿前可取消；弄湿后退出 MUST 提供继续或协助擦干，切后台和重启须恢复会话；协助完成不得触发感冒。

#### Scenario: 弄湿后请求返回
- **WHEN** 玩家在猫已湿润时请求离开护理
- **THEN** 系统提供继续护理和协助擦干，选择后者则消除湿润并结算已完成阶段，不直接丢弃会话或把湿猫退回房间

#### Scenario: 部分清洗后协助退出
- **WHEN** 玩家尚未完成清洗冲净就选择协助擦干
- **THEN** 系统仅保留已完成区段效果，不授予未完成阶段奖励，不因协助触发感冒

#### Scenario: 洗澡冷却记录
- **WHEN** 一次会话首次完成清洗冲净阶段
- **THEN** 系统记录该次洗澡完成时间并开始配置冷却；重复恢复不重置，尚未完成该阶段的取消不算完整洗澡
