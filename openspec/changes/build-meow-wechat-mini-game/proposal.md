# 提案：开发《咪头咪猫》微信小游戏

## 为什么

当前只有游戏设计文档，尚无可运行的小游戏。需要把文档中的连连看闯关与养猫循环转化为分阶段、可验收的产品能力，先形成一期可玩的 MVP，再扩展猫咪收集、收留站和背单词等长期玩法。

## 变更内容

- 新增微信小游戏核心闯关体验：连连看棋盘、匹配消除、关卡生成与难度递进、道具、结算和奖励。
- 新增轻拟真、偏治愈的猫咪养成体验：属性与精力、离线衰减、个体偏好、即时情绪、长期信任、主动邀请、疾病与医院治疗。
- 将咪窝作为可布置的生活房间，承载喂食、逗猫棒、抚摸、梳毛和擦爪；关联独立护理区，承载猫砂盆、洗澡和吹干，同窝最多三只猫共享设施且互斥占用。
- 新增猫砂日常消耗闭环：商店购买、定期铲屎、按量补砂和整盆更换；离线累积有容量边界，不增加猫砂相关疾病或收容触发条件。
- 新增可见家具与玩具的购买、背包和布置闭环，猫可实际使用猫床、猫爬架、纸箱、抓板和地面玩具；家具仅提供外观、休息位置或互动锚点，不提供被动属性优势；保存时校验实例唯一性、占地和必要设施可达性。
- 确定喂食成功立即扣物品并增加饱食度，动画不再结算；玩具按耐用型和消耗型区分；洗澡中途可协助擦干，吹干操作失误不触发感冒，其他疾病规则不变。
- 新增猫咪品种收集、经济与商城、玩家存档和云端同步能力。
- 在后续阶段扩展猫咪收留站：猫咪连续 30 天未被喂食后自动入所，原主人可在一年内按配置基准价的 2 倍赎回；满一年后原主人赎回权到期，其他玩家可按配置低价购买。并扩展背单词赚喵币玩法。
- 以 Cocos Creator 3.8+、TypeScript 和微信小游戏为客户端目标；云开发运行时及平台能力在实现前核实当前支持情况。
- 本轮只更新规划与 AI 生成提示词，不实现代码或生成游戏资源；后续由显式 apply 请求执行任务。不定义文档未说明的排行榜、支付和广告审核规则。

## 能力

### 新增能力

- `match-puzzle`: 连连看规则、棋盘与可解关卡生成、特殊方块、关卡进度、道具和结算。
- `cat-care`: 猫咪状态衰减、情绪/信任/偏好、双向互动、猫砂照护、多猫占用、洗浴恢复、疾病与治疗。
- `cat-home`: 咪窝房间与护理区导航、移动端 UI、家具布置、可达性和猫咪自主使用。
- `cat-collection`: 猫咪品种、稀有度、成长和收集解锁。
- `game-economy`: 喵币/钻石、关卡与日常奖励、分类商品、猫砂计量、耐用物实例、购买和消费。
- `player-save`: 玩家进度、生活设施、布局和护理会话的本地缓存、离线操作依赖及云端同步校验。
- `cat-shelter`: 猫咪自动入所、原主人限期赎回、一年后向其他玩家低价出售，以及收容记录和所有权转移（后续阶段）。
- `vocabulary-practice`: 分级词库、答题模式、每日奖励上限与连对奖励（后续阶段）。
- `engagement-rewards`: 每日登录、分享、激励视频和成就奖励；具体平台政策另行确认。

### 修改能力

无。当前项目没有已有 OpenSpec 能力规格。

## 影响

- 目标客户端：Cocos Creator 3.8+ / TypeScript 微信小游戏；设计文档提出的云开发数据库、云函数和云存储需要结合当前平台支持确认。
- 主要领域：关卡与棋盘算法、猫咪及玩家数据模型、货币/商城、云端持久化、小游戏场景与 UI。
- 既有依据：[meow_plan.md](../../../meow_plan.md)。现阶段仓库没有游戏源码或测试，规格以该设计文档和本次确认的决策为输入。
- 已确认决策：6×8 棋盘由 6–8 种图片重复组成 24 对；离线可继续操作，上线后由云端校验并以云端已确认状态解决冲突；每只猫连续 30 天未喂食后自动入所，原主人一年内按配置基准价的 2 倍赎回，期满后赎回权终止并开放其他玩家按配置低价购买。
- 本轮补充影响：Creator 房间/护理区场景与公共 Prefab、场景专属设备与家具配置、触控和动画状态机、空间占用与寻路、猫砂库存与拥有物交易、云端操作校验和护理存档；家具不提供被动属性加成或属性衰减减免；不采用网页框架或 localStorage。详细 UI 与可复制生成提示词见 [design.md](design.md)。
- 规划默认：每窝一个护理区、基础生活设施与少量初始物资、共享猫砂盆、精力及个体关系数据均纳入任务范围；价格、容量、周期和美术配色作为可调配置。它们是本轮明确记录的设计选择，不冒充已上线行为。
- 待产品决策：排行榜入口的排名范围与计分方式；钻石充值及广告接入是否纳入首发；特殊方块组合下的死局处理与难度验收指标。
